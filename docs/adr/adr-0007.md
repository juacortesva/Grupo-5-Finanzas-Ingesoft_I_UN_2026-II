# ADR-0007: Aislamiento de Adaptadores API y Cliente HTTP Nativo en Frontend

| | |
| :--- | :--- |
| **Fecha** | 2026-11-12 |
| **Equipo** | Grupo 5 (`@KevinVerjan`, `@Estebandido-exe`, `@josuarezvi`, `@juacortesva`) |
| **Trazabilidad** | `REQ-01` (`BR-01`..`BR-06`), `ADR-0001`, `ADR-0002`, `CT-01`, `CT-06`, `CT-09` |

---

## Estado

Aceptado

---

## Contexto

El desarrollo paralelo entre backend y frontend requiere avanzar sobre los contratos acordados (`CT-01`, `CT-06` y `CT-09`) antes de que el backend resuelva las dependencias abiertas del catálogo de opciones (`question_option`) y autenticación. Al mismo tiempo, `docs/code_style.md` prohíbe lógica HTTP dentro de componentes `.tsx`, exige tipado estricto sin `any` y maneja puntajes `Decimal` como `string`.

---

## Alternativas consideradas

- **Llamadas `fetch` o `axios` directas dentro de los componentes/hooks con datos quemados mezclados:** Se descartó porque acopla la interfaz al transporte HTTP, dificulta las pruebas unitarias y obliga a reescribir componentes cuando el backend esté disponible.
- **Librerías pesadas de estado remoto (Redux Toolkit + Axios + interceptores):** Se descartó por complejidad innecesaria para el alcance actual de `REQ-01` y por añadir dependencias adicionales al árbol del cliente.

---

## Decisión

1. Definir un puerto de interfaz por feature (`SurveyApiPort` en `features/survey/api/surveyApi.ts`) con dos implementaciones intercambiables mediante `VITE_USE_MOCK_API`: `mockSurveyApi` (adaptador simulado fiel a `CT-01`, `CT-06`, `CT-09` y `BR-06`) y `httpSurveyApi` (adaptador HTTP real).
2. Centralizar el transporte en `src/api/httpClient.ts` sobre `fetch` nativo, con inyección de token Bearer (`setAuthTokenProvider`) y parseo tipado de errores `{ "detail": "..." }` (`401`, `404`, `409`, `422`, `503`) sin usar `any`.

---

## Consecuencias

- **Ventajas:** Permite desarrollar, probar en Vitest y validar el flujo completo de `REQ-01` de forma independiente; cambiar al backend real solo requiere ajustar `VITE_USE_MOCK_API=false` sin tocar componentes ni *Custom Hooks*.
- **Compromisos aceptados:** El equipo debe mantener sincronizado `mockSurveyApi` con cualquier cambio posterior en los contratos `CT-01`, `CT-06` y `CT-09`, y regenerar `src/api/generated/schema.d.ts` con `npm run generate:api` al levantar FastAPI.
